    Changelog¶

    Unreleased¶

    • Change sets (Automation › Change sets, labdex changeset FILE): write a batch of network, host and alias changes (and deletions) as YAML, preview it (what each change does, the lint findings it adds or resolves, the firewall aliases and DNS records that change; nothing is saved), then apply it as one unit: all of it or none, one history entry per object named after the set, and each change checked against your permissions. See Change sets in the guide.

    Fixes¶

    • Install in the Marketplace seemed to do nothing for a plugin further down the list: the step that shows its signature and asks you to confirm opened above the cards, out of view. It now scrolls into view.

    For plugin authors¶

    • labdex.testing: PluginHarness loads a plugin folder, validates its manifest and calls run_, plan_, apply_, export_, endpoint_, page_, widget_ and host_view with a real Context over an inventory you give it; FakeServer is a recording HTTP server for the API the plugin talks to. See Testing in the plugin guide.
    • The docs showed ExportFile(filename, content, mimetype); the order is ExportFile(filename, mimetype, body). Fixed in the README and the plugin guide.

    Coming from another tool¶

    • Add networks and hosts from NetBox, phpIPAM or CSV files: Settings › Add from other tools, or labdex import-from netbox|phpipam|csv. It only adds (what exists is skipped), everything comes in under a zone you choose (or one per network), a preview keeps nothing, and every new object is a History entry you can revert. IPv4 only for now. API: POST /api/admin/import/external. See Coming from another tool in the guide.

    API¶

    • OpenAPI description at GET /api/openapi.json (sign in like for any call) and as labdex openapi [-o file]: every route with its methods, path parameters, who may call it and its summary, built from the code so it can't fall behind. Feed it to a client generator, Postman or Swagger UI. Bodies are described as plain JSON objects; the API table in these docs says what they hold. A test keeps the tables in the README and the docs pointing at routes that exist.

    Labels¶

    • Host labels with a QR code: Label on a host's page, or tick hosts and choose Labels to print a sheet. Each label has the fun name, hostname, addresses and zone, and a QR code that opens the host. SVG in millimetres (62 × 29, 50 × 25 or 89 × 36), so it prints true on a label printer. GET /api/hosts/<name>/label.svg?size=….
    • Cable labels with a QR code next to each cable on the Cables page (GET /api/cables/label.svg?host=&port=); the code opens the cable's trace.
    • Set the address of your labdex (Settings › General) so the codes work from outside; without it they use the address you opened labdex with. New dependency: segno (pure Python).

    Hosts¶

    • Saved searches: a Saved menu on the Hosts page keeps the search text, filters, tab and grouping under a name. Yours are private; administrators can share one with everyone. API: /api/searches. New table saved_search (migration 0035).
    • Bulk change can also add and remove features and pin a host to a zone (or let it follow its network again), next to status, runs on, tags and integrations.

    History¶

    • Net change since… on the History page (last day, week or 30 days): one row per object with what changed overall, so five edits of a host read as one diff, and an object created and deleted in between isn't listed. Also labdex diff --since 7d [--fields] and GET /api/history/changes?since=7d (24h, 2w or a date work too).

    Weekly digest¶

    • New notification event digest.weekly: one message a week with what changed, the lint errors and warnings, addresses Discovery saw that aren't in the inventory and plans waiting. Tick it on a channel under Settings › Notifications; the first one arrives a week later.

    Lint¶

    • New checks: overlapping prefixes between networks (error), a gateway outside its prefix, a DHCP range that is reversed, reaches outside its prefix or contains the gateway, an IPv6 prefix that isn't a /64 (note), and two services on one host using the same port and protocol (when they can listen on the same address).
    • Accept a finding on the Lint page (administrators): give a reason and it no longer counts in labdex lint, the dashboard or the sidebar. It stays on the page under Show accepted, the change is in History, and Count again takes it back. API: POST/DELETE /api/lint/accept; the list is the lint_accepted setting, so it's in the inventory YAML and in backups.

    Fixes¶

    • About › Updates missed a new release for hours: the release check kept its answer six hours, so the page said "Up to date" long after a release was out. It now keeps it an hour, and Check now on the card asks again at once (POST /api/about/update-check; at most every 30 seconds). The card says when it last looked. Versions are compared the PEP 440 way, so 1.24.10 is newer than 1.24.9 and a .post, rc or .dev build compares right.

    1.24.1-1¶

    Fixes¶

    • No more InsecureRequestWarning in the log for every request to a device whose certificate isn't checked (a self-signed firewall, controller or hypervisor, with "verify TLS" off): that's a setting you chose, not a problem to report again and again.

    1.24.1¶

    labdex moved to labdex-app¶

    • labdex, its Marketplace and the official plugins now live in the GitHub organization labdex-app. Old links redirect.
    • The image is now ghcr.io/labdex-app/labdex. Change it in your compose file once: ghcr.io/reykimedev/labdex stays at 1.24.0 and gets no more updates.
    • The official Marketplace is at https://labdex-app.github.io/labdex-plugins/index.json; labdex moves its official repository there by itself. The docs are at https://labdex-app.github.io/labdex/. An instance that still has the old project address (Settings › General) gets the new one; one you set yourself stays.

    Faster¶

    • The services list is about 9× faster with 1000 hosts: permission checks no longer build each host's full record (the same for DNS, racks, Discovery and the audit log).

    Plugins come from the Marketplace only¶

    • No plugin ships with labdex any more, the official ones included: the image and the wheel are labdex alone, and every plugin is installed from Plugins › Marketplace (or uploaded), downloaded and signature-checked like any other.
    • Backups are part of labdex: the backup plugin moved into the core, so every instance has its daily backup from the first start, as before. The Marketplace no longer offers it.
    • Upgrading from 1.24.0: labdex installs the official plugins you had (installed, or with an instance) from the official Marketplace by itself, at their held version if you held one, a few seconds after the start. Offline, it tries again every 15 minutes, and the Plugins page lists what's missing with an Install them now button; instances keep their settings and history meanwhile. A plugin you uninstall isn't put back.
    • The demo only has the plugins of its own image (the demo lab and backups).
    • For development: the official plugins are git submodules in plugins/ (not in the package); LABDEX_DEV_PLUGINS loads such checkouts, the tests set it.

    Fixes¶

    • labdex 1.24.0 didn't start when the official Marketplace had been added by hand before (under its name or address): it now takes that entry over. A problem setting up the official repository can no longer stop labdex from starting.
    • The release's source archive is labdex alone (it included the plugins).

    1.24.0¶

    Licence¶

    • labdex is now under the GNU AGPL-3.0 (was MIT), with a plugin exception: free to use and change, but a changed labdex, also one run as a service, has to stay open source and keep the credit to the original (see NOTICE). Plugins can use any licence; the official ones are AGPL-3.0 too. Earlier releases stay MIT.

    Patch panels and cable traces¶

    • An interface can pass through to another port of the same host: a patch panel's front port and its rear port (set on one side, both get it). Several adds a whole panel at once, every port with its rear port.
    • Trace follows a cable end to end through any number of patch panels, with each cable's label, colour and length: on a host's ports, on the Cables page and on a topology cable.

    Where is this MAC?¶

    • Discovery › Where is… finds the switch port behind a MAC, an IP address or a host, from the switches' forwarding tables; the likely port is pinned (an uplink to another switch isn't). Typing a MAC or an address in the search offers it too, and a host's Network tab shows the port next to each interface that has no cable on record.
    • SNMP neighbours 1.1 reads BRIDGE-MIB and Q-BRIDGE-MIB (per VLAN); UniFi 2.2 reports every client's switch port (wired) or access point (Wi-Fi). Publish both from their repositories.
    • For plugin authors: ctx.discovery.record_macs(source, entries).

    Sign in with OpenID Connect¶

    • Authentik, Keycloak, Authelia, Pocket ID, Zitadel …: authorization code flow with PKCE, accounts created at the first sign-in (or only existing ones), groups from the provider matched to labdex groups, administrators by group, the password form optional. Configured through LABDEX_OIDC_*; Settings › Users shows the setup and the redirect URI.

    The top bar¶

    • Help, the project's page, About, Settings and your account sit in a bar at the top; the sidebar lost its duplicate Collapse, Admin and avatar. Admin is now Settings. A Help page has the docs, issues, security reports, the keyboard and the details for a bug report.

    Release check¶

    • The update check works with GitHub, GitLab and Gitea/Forgejo (Codeberg …) from the project's address (Settings › General; default github.com/reykimedev/labdex), says why a check failed, and tries again after ten minutes instead of six hours.

    CI¶

    • Pushes get a quick lint; the full tests run on pull requests.
    • Release images are built on native amd64 and arm64 runners in parallel (no emulation) and joined into one multi-arch image; each architecture keeps its own build cache.
    • Dependabot keeps GitHub Actions, npm, Python, the base image and the plugin submodules up to date, as weekly pull requests.

    1.23.1¶

    Faster image builds¶

    • The UI is built once on the runner's own platform instead of again under arm64 emulation; system packages and Python dependencies are a layer that only changes with pyproject.toml; layers are cached in the registry (:buildcache) between releases.
    • CI uses actions that run on Node 24.

    1.23.0¶

    Plugin versions and updates¶

    • A plugin's details in the Marketplace show what's new since your version and every version its repository offers, with release notes and dates. Install any of them, newer or older.
    • Switch back: an update keeps the version it replaced, so going back is one click (and works offline). Going forward again works the same way.
    • Stay on a version: a held plugin gets no update offers and never updates by itself.
    • Withdrawn versions: publishers can withdraw a version with a reason. Whoever has it is warned in the Marketplace and by notification, and updates skip it.
    • Update checks every six hours (Admin › Plugins › Updates): Tell me (the default) sends a notification per new version once; Install official updates installs updates signed with the labdex project key by themselves, into History; Off. New notification events: plugins.update, plugins.updated, plugins.update_failed, plugins.withdrawn.
    • Official plugins have a CHANGELOG, shown in the Marketplace.

    Plugins in their own repositories¶

    • Every plugin that ships with labdex moves to a repository of its own (labdex-plugin-<id>), included in labdex as a git submodule. Tagging a version there signs it and attaches it to a GitHub release.
    • The official Marketplace is its own repository, labdex-plugins: it lists the plugin repositories, checks every release's signature and publishes a signed index at reykimedev.github.io/labdex-plugins, which labdex trusts out of the box.
    • For publishers: labdex plugin build-index (a Marketplace from plugin repositories), labdex plugin yank (withdraw a version), labdex plugin fetch-repo (keep older versions when rebuilding a repository), tools/plugin_repo/make_plugin_repo.py (start a plugin repository with its release workflow). An index can now list several versions of a plugin and point at archives anywhere.

    Releases¶

    • labdex and every plugin are released by publishing a GitHub release (tag v<version>); the workflow checks the tag against the code with a clear message, builds, signs and attaches everything to that release.
    • A release's description gets that version's CHANGELOG section (below anything written by hand), and CHANGELOG.md is attached. The source archive includes the plugins.
    • Plugin repositories: .releaseignore keeps files out of the release zip (labdex plugin prune); the Marketplace finds new labdex-plugin-* repositories by itself and checks for new releases every hour.

    Also¶

    • README, docs and the About page say plainly that labdex was built with AI and is meant for home labs only.
    • Links point at the real addresses (github.com/reykimedev/labdex, its Pages and ghcr).

    1.22.0¶

    Topology¶

    • Cables are drawn in their own colour. Switch to colouring by speed on the legend (remembered in your browser and in saved views); thicker is still faster. White and black cables get a thin edge so they show on both themes.
    • A host's fun name is a label of its own above the host, in bold; the hostname sits below in mono, quieter. Drag the fun name wherever it reads best: it stays there (shared, with the layout) and moves with the host.
    • Port names are small tags further out along the cable, clear of the host and its name.
    • Snap to grid works: the dots were drawn half a step off the points things snap to. The dots are a little easier to see too.
    • Hypervisor boxes leave room for their guests' names.

    Policy¶

    • Network › Policy has a second tab, On the firewalls: every firewall that enforces the matrix shows its pending rule changes, the rules no policy explains and which zones labdex manages, with Sync policy rules right there. It replaces the OPNsense instance's Firewall policy tab (old links land on the new tab).
    • For plugin authors: place: policy on a page (with an action) puts it there.
    • OPNsense plugin 1.3.

    1.21.0¶

    Plugin Marketplace¶

    • Plugins › Marketplace: every plugin that ships with labdex and everything your repositories offer, in one place: search, categories, Not installed / Installed / Updates, and a details view with what each plugin brings (settings, actions, pages, where it comes from). Installing a plugin that ships with labdex is one click and downloads nothing; a download from a repository is signature-checked and confirmed as before.
    • Not everything is installed by default. A new labdex starts with Backup, File exports, Ansible runner and nmap. An upgrade keeps those plus every plugin you have an instance of, so nothing you use goes away.
    • Uninstall a plugin that ships with labdex from the Marketplace (refused while it has instances). It stays part of labdex; install it again any time.
    • A plugin's page says when it isn't installed, with an Install button.
    • Admin › Plugins keeps upload, repositories and signing keys; the repository list now sends you to the Marketplace to install.
    • The Marketplace view is open to everyone who can see integrations; installing needs an administrator, as before.
    • An inventory import keeps the instance's plugin choices (and the official-repository setting) instead of resetting them.

    1.20.0¶

    Cables the switches see¶

    • Inventory › Cables › Seen by switches: cables switches report that aren't on record yet (tick and add, or ignore for good), ports where a switch sees something else than the record (keep it, or use what's seen), and neighbours labdex doesn't know (add them as hosts, prefilled). A cable both ends report shows once; adding one goes through the host's normal checks and into History.
    • New plugin SNMP neighbours: reads LLDP-MIB and CISCO-CDP-MIB over SNMP v2c or v3 (SHA, SHA-256, SHA-512, MD5; AES-128), reports whether each switch answers and shows its neighbours on the host. It starts with hosts tagged snmp. Its SNMP client is labdex's own (no new dependency) and is tested against net-snmp.
    • UniFi 2.1: signed in with a local account it also reads LLDP tables, device uplinks and the switch port of every wired client.
    • Ends are matched to hosts by any name labdex knows, an interface's MAC, or an address; port names match whatever their case, and the cable uses the host's own spelling.

    For plugin authors¶

    • ctx.discovery.record_links(source, links) reports what a device sees on its ports.
    • applies_to in a manifest: what a new instance applies to (the default stays *).

    1.19.0¶

    A UI pass: every page looked at in light, dark and on a phone.

    Fixed¶

    • A network's page showed its id (GPUUVNFHZD) as the title instead of its name.
    • A host's Plugins tab was blank when no plugin works per host; it says so now.
    • A host's DNS records ran off the screen on a phone.
    • The Overview dashboard had empty stretches and cut off Last changes; its default layout is tighter (updated for everyone who never changed it).
    • A plugin page's title (and any name set in mono) was smaller than every other title.

    Controls¶

    • The last radio buttons and tick lists are gone: the home zone (follow the primary interface / choose), a secret's source (own value / from the vault) and a plugin per host (follow / always on / off) are segmented controls; network pickers in plugin settings are chips; yes/no columns in plugin tables are switches.     0.6.1¶

    Approvals and change windows¶

    • Approval policies (Admin → Approvals & windows). A plan is matched, top to bottom, by integration name, the zones of the hosts it runs for and how it was started (by someone, by a hook, on a schedule). The policy sets the approvals needed (0 = applies by itself), who may give them (users and @groups; empty = anyone who may apply the integration), whether whoever started the plan may approve it, a delay after planning, and a change window. Without a match it's as before: you approve your own plans.

    • A plan the inventory has moved past is planned again when it's approved or its window opens. If the new plan has the same changes, the approvals carry over; if not, it waits for approval again. A newer plan for the same action keeps the approvals of the one it replaces the same way.

    • Each host has a DNS tab: extra records (alias CNAME, A/AAAA, TXT, SRV, MX) with placeholders ({target}, {fqdn}, {ip4}, {ip6}, {host}, {fun}), and a switch per fun name to publish it or not.
    • An alias with an empty value points at the primary record, so it follows when the primary interface changes.
    • These records are part of the inventory (YAML, exports, Technitium sync). The Technitium module's per-host "extra records" moved here on upgrade.

    About¶

    • About page (user menu, Admin → General): version, schema, database, plugins with versions and trust, and this changelog. Optional check for new releases on GitHub (off by default; Admin → General).

    0.5.1¶

    Zones¶

    • A host's home zone now follows its primary interface's network (or the first interface in a network). Choose "pin" to keep a zone of your own. When a network changes zone, hosts that follow it move along, with a history entry.
    • Zone is picked as area + trust level. New hosts no longer default to a zone that may not exist.
    • Every address shows its network's zone. Someone who may see a zone can now view (not edit) hosts with an address there, e.g. the edge firewall for a DMZ-only user. The sidebar puts such hosts in the zone they can see.
    • Upgrading pins exactly the hosts whose zone differed from their network.

    VIPs¶

    • New host kind "VIP": a shared address with a protocol (CARP, VRRP, keepalived, kube-vip, MetalLB, anycast) and member hosts. It gets DNS, firewall aliases and services like any host. Members list it on their Network tab and get labdex_vips plus a vip_<name> group in Ansible. The VIP itself is never an Ansible target and has no MAC. Hostname type vip added.
    • Member renames and deletions are followed; YAML import/export keeps members.

    Fixes¶

    • Host pickers (Discovery "add to host…", VIP members) are no longer cut off by the table; full names, keyboard selection, flips upwards near the bottom.
    • Migrations on SQLite run with foreign keys off, so rebuilding a table can't cascade-delete interfaces.

    • UI query cache (stale-while-revalidate): pages show the last answer at once and refresh in the background; every change, from any tab or the CLI, arrives on the event stream (revision) and refreshes what's on screen.

    • Host links prefetch on hover; saving a host writes the answer into the cache.
    • The host picker loads four fields instead of whole hosts.
    • Host list renders 200 rows at a time; search no longer matches field names.
    • Server: weak ETags with 304 Not Modified on every GET; a per-revision host index behind the host list, sidebar and counts (1000 hosts: host list 45 ms, sidebar 60 ms, slim list 5 ms).
